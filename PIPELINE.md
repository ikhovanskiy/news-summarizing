# news pipeline — единый детерминированный сбор и суммаризация

> Это про **бэкенд новостей** для команды `/news`. SvelteKit + TypeScript
> приложение одновременно обслуживает viewer и API; локально всё запускается
> одной командой `npm run dev`.

Цель: каждый запуск `/news` собирает данные и форматирует отчёты **одинаково**,
а субагенты НЕ импровизируют — не выдумывают данные и не меняют формат.

## Файлы пайплайна

```
news/
  channels.json      # каналы по категориям; world также хранит группу риторики
  collect.py         # ЕДИНСТВЕННЫЙ сборщик сообщений из Telegram
  prompts/
    world.md         # канонический промпт + формат (мировые)
    crypto.md        # канонический промпт + формат (крипто)
    invest.md        # канонический промпт + формат (инвестиции)
```

## Поток данных

```
server: collect.py  ──►  collection job result            (сырьё: сообщения по каналам)
                       │
             digest_server.py collect
                       ▼
             /tmp/news-raw/{world,crypto,invest}.md
                       │
            3 субагента (по prompts/<cat>.md)
                       ▼
                 /tmp/{world,crypto,invest}-news.md        (готовые отчёты)
                       │
                  digest_server.py push
                       ▼
            GET/PUT /api/digests/:category ──► persistent NEWS_DATA_DIR
                       │
                       ▼
                 Svelte-вьюер
```

Перед вычислением нового диапазона `digest_server.py pull <category>` загружает
канонический предыдущий дайджест с сервера в оба локальных имени (`/tmp/<category>.md`
и `/tmp/<category>-news.md`). Затем `digest_server.py collect` запускает `collect.py`
на сервере и скачивает сырьё для локального анализа. После успешной генерации `push`
публикует новый файл. Локально helper автоматически использует
`http://127.0.0.1:5174`; `NEWS_SERVER_URL` нужен только для другого сервера.
API не требует авторизации.

## collect.py — одна политика сбора

1. В рабочем `/news`-потоке запускается только на сервере через collection API.
2. Сервер всегда передаёт `--source scrape`, поэтому сбор сразу идёт через публичный
   веб-превью `https://telegram.me/s/<channel>` с пагинацией по дате (только stdlib).
3. Дедуп по id сообщения, сортировка по времени → детерминизм (одинаковый набор от запуска к запуску).

Для `world` записи в `channels.json` имеют вид
`{"name": "channel", "group": "...", "note": "необязательное примечание"}`.
Допустимые группы: `russian`, `ukrainian`, `european`, `american`. Коллектор добавляет
группу и примечание в заголовок каждого блока `CHANNEL`, а `prompts/world.md` требует:

- отдельный разбор фактов и риторики каждой группы;
- сравнение сообщений об одном событии российско-украинского конфликта;
- явное разделение того, где фактический смысл сходится и где версии расходятся.

```bash
# Запустить серверный сбор и скачать результат:
python3 ~/home/news/digest_server.py collect crypto \
  --date-from 2026-06-01 --date-to 2026-06-01
```

Серверный stdout передаётся клиенту, после чего сырьё сохраняется в
`/tmp/news-raw/crypto.md`.

## Где что менять

- **Список каналов и группы риторики world** → только `channels.json` (команды `/news*` их не дублируют).
- **Формат отчётов** → только `prompts/<cat>.md` (команды формат не содержат, поэтому он
  одинаков для `/news` и для standalone `/news-crypto` / `/news-invest` / `/news-world`).
